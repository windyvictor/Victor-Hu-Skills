# 受控科研写作（Controlled Scientific Writing）

## 0. 这份文件补的是什么

research-copilot 原本的写作规则（见 `academic-writing.md`）是**定性**的：优先具体表达、减少空泛套话、
语言强度要匹配证据强度。这些原则都对，但有两个问题：

1. **没有阈值**。"长句"多长算长？"套话"具体是哪几个词？两个人执行结果可能完全不同。
2. **没法验证**。写完与否、好坏与否，只能靠再读一遍凭感受判断。

ASD-STE100（Issue 9，2025-01-15）提供的是与之互补的东西：**一套能用机器判定的硬约束**。
它的出发点不是文风偏好，而是"用大量硬约束换极高的可解析性"——
一个意思只准一个词、时态收窄到若干种、句长/段长有明文上限、"什么算一个词"有明文计法。

**但 STE 是为航空维修文档编纂的，直接套到论文上会出事。** 下面 §3 的豁免清单就是这件事的全部关键。

三份文件的分工：

| 文件 | 管什么 |
|---|---|
| `academic-writing.md` | **科学内容与论证**：保留科学事实、每句话承担功能、篇幅分配、hedging 与证据强度匹配 |
| **本文件** | **语言层的机械底线**：句子/段落/用词的可检查约束 + 脚本 |
| `references/mathematical-proof.md` | 推导过程的写法；与本文件的数学豁免 §3 配套 |

顺序是：**先用 `academic-writing.md` 把论证做对，再用本文件把语言擦干净**。
反过来做会得到一篇文字干净但论证空洞的稿子。

## 1. 四档：先选档，再写

| 档 | 约束来源 | 用在什么场合 |
|---|---|---|
| **A · 学术档**（默认） | STE 的可机械判定子集 **减去** §3 的豁免 + `assets/academic-domain-terms.txt` 术语豁免 | 论文正文、摘要、引言、方法、实验、基金申请书、组会讲稿 |
| **S · 严格 STE 档** | 53 条规则全上，不豁免 | 设备操作规程、实验安全须知、数据采集 SOP、需要交付给工程方照做的文档 |
| **C · 中文受控写法** | §4 的 10 条 | 所有中文写作 |
| **0 · 停用词典** | 只跑结构类规则（句长/被动/名词化/套话） | 只想清结构、不想被词表打扰时 |

**换档就是换脚本的 `--mode`**：`--mode academic`（默认）/ `--mode ste` / `--no-dictionary`。

> 同一份稿件跑两档是有价值的：报告里"被学术豁免屏蔽了 N 条"那一栏，
> 正好告诉你哪些地方是"论文里可以，但在操作规程里会被打回"。

## 2. 继承：STE 里那些可以直接用在论文上的规则

这些规则与学术写作的目标一致，照做即可。括号内为 ASD-STE100 Issue 9 的规则号。

| # | 规则 | 阈值 | 学术档要不要打折 |
|---|---|---|---|
| 1 | 名词串长度上限（2.1） | multi-word noun ≤ **3 词** | 放宽：术语型串（reinforcement-learning-based policy）不受限 |
| 2 | 动词形式白名单（3.2） | 只用不定式/祈使/一般现在/一般过去/一般将来/过去分词作形容词 | 保留，但完成时豁免（见 §3） |
| 3 | 禁用进行时（3.2） | `is running` 类 | 保留，学术写作本就少用 |
| 4 | 主动优先（3.6） | 仅当 agent 未知才用被动 | **降为建议**：方法章 `was trained for 200 epochs` 完全可接受 |
| 5 | 一句一事（5.2） | 一个陈述句承载一个信息单元 | 保留，这就是 `academic-writing.md` 的"每句话必须承担功能" |
| 6 | 句子长度上限（5.1 / 6.3） | 程序句 **20 词**、描述句 **25 词** | **放宽到 35 词**：见 §2.1 |
| 7 | 段落句数上限（6.6） | 一段 **≤ 6 句**、一段一主题 | **放宽到 8 句**；6 句仍是最好的自检法：把各段首句抄下来就是全文提纲 |
| 8 | 一段之内相关才同段（6.5） | — | 保留 |
| 9 | 多步骤用竖排列表（4.3） | 一项一步、每项独立成句 | 保留（算法伪代码、超参清单、条件下拉清单） |
| 10 | 不用缩写（4.2） | `doesn't` → `does not` | 保留，完全一致 |
| 11 | 不用分号（8.1） | `;` → 拆句或改连接词 | **降为建议**：学术文体允许分号分隔并列条件 |
| 12 | 禁止短语动词（9.3） | `carry out` → 具体动词 | **改写适用**：见 §2.2 |
| 13 | 术语一致（9.4） | 同一概念全篇一个词 | 保留，这是硬要求 |
| 14 | 计词有明文（8.4–8.7） | 数字、数字+单位、缩写、字母数字标识、引文、括号内容各算 1 词 | 保留 |
| 15 | 安全提示三段式（7.1–7.3） | 命令/条件起句 → 解释 → 具体危害 | **迁移使用**：见 §2.3 |

### 2.1 为什么句长放宽到 35 词

STE 定 20/25 词，是因为操作数|=\ 维修工学徒要在手上沾着油污时读一句就必须能执行。
论文读者的处境不同：他们能回读、能查公式。

但也不能无限长。35 词是"一次工作记忆能装下的论证单元"的常用上限，
超过之后读者需要在脑内维护栈。相比之下原本默认的 25 词会逼你把方法章的句子切得过碎，
反而破坏因果链的连贯性。

### 2.2 短语动词：STE 的替换词不能照抄

STE 给的替换是 `DO` / `MEASURE`——那是给维修手册用的。学术写作里正确的做法是换成**精确动词**：

| STE 官方替换 | 学术写作应该用 |
|---|---|
| `conduct (v) → DO` [p.198] | `run experiments` / `train the model` / `evaluate on X` |
| `perform (v) → DO, MEASURE` [p.331] | `solve` / `search` / `measure` / `compute` |
| `obtain (v) → GET` [p.319] | `derive` / `collect` / `achieve`（视宾语而定） |
| `provide (v) → GIVE` [p.344] | `supply` / `show` / `implies` |
| `facilitate (v) → HELP` [p.245] | `allow` / `enables` |

上表这些词已逐条回原书核验为"未核准"，页码见每行别注。
STE 给的替换词（`DO` / `GET` / `GIVE`）不能直接照抄，因为它们在学术句里通常不够精确——
替换的目标是**更具体的动词**，不是更短的词。

### 2.3 §7 安全提示三段式的迁移用法

它是全套 STE 里最值得挪用、也最容易被忽略的一部分。结构：

```
<命令或条件>           ← 起句必须是动作，不能是背景说明
<解释：为什么要做>      ← 说明机制
<具体危害/后果>         ← 不说清后果，读者会跳过
```

在论文里，它适合写三类东西：

- **可复现性注意事项**：不要写"注意随机种子"，要写"固定随机种子并记录 torch/CUDA 版本；
  CUDA 11.x 与前代在 nondeterministic reduction 上行为不同；不固定则同一配置两次运行的
  mAP 可能相差 0.4 以上，跨 paper 的 ablation 会失效"
- **适用性限制**：在什么条件下本方法不成立，以及不成立的后果是什么
- **实验操作中的真实风险**（机器人、化学、医疗场景）

## 3. 豁免：这份融合真正的关键

**核心事实：`may` 和 `should` 在 ASD-STE100 里是"未核准词"。**

| 词 | STE 原书给出的核准替代 | 出处 |
|---|---|---|
| `may (v)` | `CAN (v)` / `POSSIBLY (adv)` | p.309 |
| `should (v)` | `MUST (v)` / `IF (conj)` | p.377 |

而 `academic-writing.md` **明确要求**使用 hedging——证据只支持较弱结论时要用
`may`、`suggests`、`is consistent with`。也就是说：**把完整 STE 套到 research-copilot 的输出上，
会把这份 Skill 自己要求的谨慎语言全部删掉。** 这不是需要微调的噪音，这是方向性冲突。

同类冲突还有一整批，集中在数学与形式化写作。下面每一行都已回原书字典核对词条与页码：

| 未核准词 | STE 官方替换 | 出处 | 为什么必须豁免 |
|---|---|---|---|
| `assume (v)` | `THINK (v)` | p.169 | 定理陈述的前提。"Assume X holds" 不是"我们认为 X" |
| `denote (v)` | `SHOW (v)` | p.212 | "We denote the value function by V" 改成 We show 后语义全变 |
| `bounds (n)` | `LIMIT (n)` | p.179 | 数学里 bound 与 limit **是两个不同概念**，替换即错误 |
| `verify (v)` | `MAKE SURE (v)` | p.422 | "verify the assumption" 是标准数学动作 |
| `integral (adj)` | `PART (n)` | p.286 | definite integral 不是某个部件 |
| `partial (adj)` | `NOT FULLY` | p.329 | partial derivative（偏导数）是术语 |
| `following (adj)` | `THESE (adj)` / `FOLLOW (v)` | p.254 | "the following theorem" 是数学写作惯例 |
| `including (prep)` | `THRU (prep)` / `WITH (prep)` | p.280 | 学术列举的标准介词 |
| `however (adv)` | `BUT (conj)` | p.272 | 段首 However 是学术惯例；改成 BUT 只在个别语境下更顺 |
| `respectively (adv)` | `RELATED (adj)` | 已核验 | "A and B are 3 and 5, respectively" 无等价替换 |

处理方式写在 `assets/academic-domain-terms.txt`（**138 条**，每条注明豁免理由）。
脚本在 academic 档下按此表屏蔽这些词，被屏蔽的条目会计入报告末尾的"已豁免"统计，
不会静默消失。

### 3.1 学术豁免总表

academic 档下脚本对这些规则做的处置（即 `scripts/check_controlled_writing.py` 的 `ACADEMIC_EXEMPT`）：

| 规则 / 类型 | 处置 | 理由 |
|---|---|---|
| 拉丁缩写（`et al.` `e.g.` `i.e.`） | **丢弃** | 学术体例要求，不是违规；只要求全篇一致 |
| 完成时（3.2） | hard → warn | 叙述既有文献的累积证据时保留现在完成时 |
| 助动词被动构造（3.4） | hard → info | `can be derived / can be solved` 是数学写作标准表达 |
| 被动语态（3.6） | hard → warn | 方法章允许被动态 |
| 英式拼写（1.14） | hard → warn | 只要求全篇一致，不强制美式 |
| 句长超限（5.1/6.3） | 按 35 词重新判定 | 见 §2.1 |
| 段落超长（6.6） | 按 8 句重新判定 | 方法章允许较长段落 |
| 分号（8.1） | hard → warn | 允许分号分隔并列条件 |
| 列表项标点（4.3） | hard → info | 条目逗号收尾不强制 |
| 条件位置（5.4） | → info | 论证需要决定语序 |
| `must` 误用（5.3） | → info | 论文少用祈使式，基本不适用 |
| NOTE（5.5） | → info | 仅写可复现性说明时适用 |
| 安全指令（7.2/7.3） | → info | 仅当文档确有 WARNING/CAUTION |
| 未核准词（1.1） | hard → **warn** | 词表源自维修语言；术语已在豁免表屏蔽，其余属建议 |
| 名词串超 3 词（2.1） | 保持 info | 术语串不受限 |
| `-ing` 用法（3.5） | 保持 info | 仅提示 |

### 3.2 反向提醒：看似违规其实核准的词

别用"常识"纠这些——它们在 Issue 9 里**是核准词**：

`APPROXIMATELY` · `SUFFICIENT` · `SUBSEQUENT` · `THUS` · `WHILE` · `SEQUENCE` · `INTERVAL` · `DURING`

特别地 `THUS` 是核准词，而 `THEREFORE` 不是（替代就是 `THUS` / `AS A RESULT`，p.402）——
这个方向上纠正是对的，但反过来把 THUS 改成 THEREFORE 就是错的。

## 4. 中文受控写法（10 条）

中文没有官方受控规范，以下是 STE 原则的中文等价物。原则相同：**用硬约束换可解析性**。

| # | 规则 | 反例 → 正例 |
|---|---|---|
| 1 | **一句一事**。陈述句 ≤ 30 字，步骤句 ≤ 20 字（学术档放宽到 40 字） | "我们把参数调大以后发现收敛速度虽然变快了但最终精度有所下降" → 拆两句 |
| 2 | **"的"链 ≤ 2 层**。连续定语超过两层就改写 | "基于深度强化学习的面向拆垛场景的多目标优化方法" → 拆分式 |
| 3 | **动词优先**。删掉"进行 / 加以 / 予以 / 作出 / 做一个……的操作" | "对模型进行训练" → "训练模型" |
| 4 | **主动优先**。能说"我做了 X"就不说"X 被……所" | "该结论已被验证" → "实验验证了该结论" |
| 5 | **一段一义，一段 ≤ 5 句**（学术档 8 句）。步骤用有序列表，一行动作一行 | — |
| 6 | **同义归一**。同一概念全程一个词：不要"图片 / 图像 / 图幅 / 图表"混用 | — |
| 7 | **砍冗余副词与套话**：非常、其实、实际上、需要注意的是、众所周知、在一定程度上 | — |
| 8 | **结论先行**。先给判断，再给理由 | — |
| 9 | **少用"其/此/该"指代**。指代超过一句就重述名词 | "该方法对其进行了优化" → "该方法优化了损失函数" |
| 10 | **数字紧贴量词**，不用"若干/大约/一定程度上"代替具体值 | "训练若干个轮次" → "训练 200 轮" |

## 5. 脚本怎么用

```bash
python3 scripts/check_controlled_writing.py 稿件.md              # 学术档（默认）
python3 scripts/check_controlled_writing.py 稿件.md --mode ste   # 严格档，用于对照
python3 scripts/check_controlled_writing.py 操作规程.md --mode ste
python3 scripts/check_controlled_writing.py 中文稿.md --lang zh
python3 scripts/check_controlled_writing.py 稿件.md --json       # 给程序消费
python3 scripts/check_controlled_writing.py 稿件.md --strict     # 有 hard 问题时退出码 1
cat 段落.md | python3 scripts/check_controlled_writing.py -
```

**按行自动判语言**：中文行走中文引擎，英文行走 STE 引擎（用空行占位保住原始行号），
所以中英混排的稿件（中文正文 + 英文摘要）一次跑完，不需要分开处理。

报告怎么读：

- `hard` —— 在学术写作里也是明确错误：缩写（如 `doesn't`）
- `warn` —— 应当处理：模糊动词、完成时、超出学术档句长上限的句子、套话
- `info` —— 只作提示：术语型名词串、`-ing` 词、依赖上下文判断的例行提示
- "已按科研豁免屏蔽 N 条" —— 不是问题被藏起来了，是这些东西在论文里不该报警。
  想知道被藏了什么就跑 `--mode ste` 对比。

底层两个引擎（`check_ste_compliance.py` / `check_plain_language.py`）也可以单独调用，
参数与 output-escalation 技能里的版本一致。

### 5.1 什么时候必须跑

| 场合 | 跑几遍 |
|---|---|
| 写完一节 | 一遍，`--quiet` 看分数，掉分就展开看报告 |
| 投出前 | 至少两遍：academic 档看语言，ste 档对照看被豁免的部分有没有真问题 |
| 收到审稿Reply的意见后逐条改完 | 一遍，确认没有引入新的 hard |
| 改写他人文字后（防 mosaic plagiarism） | 一遍；脚本只管语言，改写是否越界仍需人工逐句核对 |

### 5.2 已知边界

- **只报线索，不做终判**。术语 vs 冗词、hedging 是否恰当，机器判不了。
- 词表是 243 条精选版，不是全部 1274 条未核准词，**漏报是允许的**，误报才是要防的。
- 中英混排时按行判语言，一行同时含中英的句子会判到字符占比较高的一侧；
  这类句子偶尔会漏检，可用 `--lang both` 强制两边都跑对照。
- 中文引擎对"进行研究发现"这类短语给出的建议是语法正确的词干，但不一定是最佳改写。

## 6. 一页速查

写作时先自查这 8 项，再跑脚本：

- [ ] 一句话 ≤ 35 词 / 40 字；超了就切
- [ ] 一段 ≤ 8 句，且只讲一件事；把各段首句连起来读，应当就是提纲
- [ ] 同一概念全篇一个词（术语一致性）
- [ ] 没有 `utilize / facilitate / conduct / obtain / provide / therefore / due to / prior to`
- [ ] 没有 `doesn't / can't` 这类缩写
- [ ] 动词尽量具体：`run / train / solve / measure / derive`，而不是泛动词
- [ ] hedging 强度匹配证据强度（保留 `may / suggests`，别被 Inspector: 0 改掉）
- [ ] 没有"值得注意的是 / it is worth noting that / leverage / delve into"这类套话
