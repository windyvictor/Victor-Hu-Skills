# output-escalation

> **输出升维阶梯** —— 为一条消息选最省读者力气的介质：从受控文字，到图、交互网页、
> 讲解视频、可丢弃小工具，共五级；附 ASD-STE100 受控英语（Issue 9）的完整实现。

## 解决什么问题

大多数回复的默认介质是文字，但文字不总是最省力的介质。读者的成本在「把线性符号在脑内
重建成结构」这一步——当这一步变贵时，就该换介质。本技能给出的是一套**选级判据**和
**每级的质量底线**，而不是「多配几张图」的泛泛建议：

- **升维判据**：重读信号、结构信号、空间信号、时间信号、试探信号、重复信号——命中就考虑升一级；
- **降级判据**：一句话能说清却做了视频、产出时间远超问题重量、对方只在手机上看——必须停在低级；
- **第一原则**：先判断读者的力气该花在哪里（记住结论 / 看清结构 / 自己试探 / 跟时间线 /
  反复操作），再选介质。升维的正当理由永远是「阅读是瓶颈」，不是「这样显得完整」。

另外，本技能内置 **ASD-STE100 Simplified Technical English（Issue 9, 2025）的完整实现**：
Part 1 全部 9 节 53 条写作规则 + Part 2 受控词典机制（875 核准词 / 1274 未核准词，
附 244 条高频替换表），并配三个可执行检查脚本。这使「写出让读者不必重读的文字」从
文风建议变成可机械检查的硬约束。

## 何时触发

- 用户要求「解释 / 讲清楚 / 画个图 / 做可视化 / 做个讲解网页 / 做个讲解视频」；
- 内容涉及结构、流程、动态、对比、空间或时间推理，纯文字明显费力；
- 需要写**操作手册、维修手册、SOP、安全规程**或需翻译的技术文档（受控英语的原生场合）;
- 用户点名「ASD-STE100」「受控语言」「检查这段英文有没有违规」「简化这段英文」。

**不触发**：结论唯一、无结构、无争议的简单问题——直接答（R0），够用就不要升。

## 典型用法

> 「把这套算法的思路给我讲清楚，别只扔一段文字。」
> 「这个概念画个图 / 做个能拖动的网页 / 剪个两分钟的讲解视频。」
> 「帮我写一份操作规程，要求符合受控英语。」
> 「检查这段英文有没有违反 ASD-STE100。」

工作流：判级（并说明理由）→ 先把文字写成受控风格并跑检查脚本 → 按对应 reference
的硬约束造介质 → 自检 → 交付。各级不是互斥的，是**叠放**的——网页的文案、图注、
视频旁白，都要过 R1 这一关。
