# R3 — 单文件交互网页（HTML Explainer）

Karpathy 原话："Ask for output in HTML to get a beautiful, interactive webpage."
这一级的价值在于**读者能自己动手**——拖动、点击、悬停、看动画。静态图文做不到这一点。

---

## 1. 何时升到 R3

- 读者会问"**如果我把 X 调大**会怎样" → 给滑块。
- 读者会问"**它是怎么一步步变成这样的**" → 给时间轴/播放按钮。
- 内容有**多个视角**，需要一页看全但不能同时堆满 → 给标签页/折叠。
- 需要**发出去一份**自解释的东西（同事、学生、客户），对方不需要你解说 → 网页。
- 需要**图表 + 公式 + 代码**混合呈现 → 网页最顺。

**不要升的情形**：答案是一段话；对方只要一张图；你会在 10 分钟后自己讲一遍。

## 2. 工程硬约束（不可违背）

| # | 约束 | 理由 |
|---|---|---|
| 1 | **单文件自包含**：CSS/JS 全部内联，一个 `.html` 双击就能开 | 移动/发送不丢依赖 |
| 2 | **外部库走 CDN，且只走成熟库**（KaTeX、Chart.js、D3、Three.js 的 UMD 版） | 避免构建步骤 |
| 3 | **禁止引入构建链**（webpack / vite / npm / TS 编译） | 交付物必须是源文件本身 |
| 4 | **主题自适应**：用 CSS 变量 + `@media (prefers-color-scheme)`，浅色和深色**都要能读** | 用户环境不可控 |
| 5 | **对比度 ≥ 4.5:1**；浅底深字 / 深底浅字；**绝不深底深字** | 可读性底线 |
| 6 | **响应式三档**：≥1200 / 768 / 375 | 手机也要能看 |
| 7 | **首屏 3 秒内可读**：不要开场白屏动画；先给结论 | 读者耐心有限 |
| 8 | **动效克制**：入场 ≤ 400ms；循环动画可暂停；尊重 `prefers-reduced-motion` | 动效是辅助不是主角 |
| 9 | **无网络也能看懂核心内容**：字体 fallback 到系统字体，关键图形用内联 SVG | 离线场景 |
| 10 | **体积控制**：单个 HTML 目标 < 1MB；大图转 SVG 或压缩 | 加载速度 |
| 11 | **无障碍**：语义标签（`<main>` `<section>` `<h1-h3>`）、键盘可达、`aria-label` | 基本素养 |

## 3. 页面叙事骨架

顺序不要改。这是被验证过的"讲清楚一件事"的最短路径。

```
① Hero：一句结论（大字号）+ 一句"这是什么"（小字号）
② TL;DR：3 行要点，用列表，每行 ≤ 20 字
③ 主角区：核心交互演示或主图（占最大版面）
④ 分解：每一块一节 → 小节标题 + 一句话 + 一个小图/小演示
⑤ 边界：什么情况下不适用、常见误解、反例
⑥ 收尾：一句话总结 + 下一步动作
```

**为什么先给结论**：读者是来拿东西的，不是来被铺垫的。想留悬念的是小说。

## 4. 交互模式库（可直接抄）

| 模式 | 实现 | 适合 |
|---|---|---|
| 参数滑块 | `<input type="range">` + `input` 事件重算 + 立即重绘 | 展示敏感度、权衡、阈值 |
| 时间轴 scrubber | 滑块映射到进度，位置同步更新画布 | 演示演化过程 |
| 悬停高亮 | `mouseenter/mouseleave` 改透明度 | 复杂图中指认部件 |
| 点击展开 | `<details>` 或自写 toggle | 分层信息（概要 → 细节） |
| 双栏对比 | 两个并排面板，共享控件 | A/B 方案、前后对比 |
| 状态机走查 | 一排按钮切换状态，画布重绘 | 协议、流程、生命周期 |
| 单步/连续播放 | `requestAnimationFrame` + 速度倍率 | 算法逐步执行 |
| 数据表排序筛选 | 纯 JS，无库 | 结果对照 |

## 5. 数学与公式

- 用 **KaTeX**（CDN，比 MathJax 快）：`<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/katex@0.16/dist/katex.min.css">`
- 行内公式用 `$...$`，独立公式用 `$$...$$`，最后调用 `katex.render`/`renderMathInElement`。
- 公式下方必须有一句**人话解释**。公式不是解释，公式是精确化。

## 6. 工作流

1. 复制 `assets/html-explainer-template.html` 到工作目录并改名。
2. 改 Hero 与 TL;DR（先用 R1 受控写法写完文案）。
3. 填主角交互区——**先让数据/状态跑起来，再美化**。
4. 逐节补分解内容。
5. 切到浅色/深色各看一遍（浏览器 DevTools 模拟 prefers-color-scheme）。
6. 缩到 375px 宽看一遍。
7. 用 `present_files` 打开预览交付。

## 7. 常见错误清单

- [ ] 用了 `#fff` 硬编码背景，深色模式下白底刺眼 → 换成 CSS 变量。
- [ ] 深色主题下文字仍是深灰 → 对比度不合格。
- [ ] 引了 React CDN 又没写 JSX 编译 → 打不开。
- [ ] 首屏是一个 loading 动画 → 读者走了。
- [ ] 图表颜色只为了好看，涨跌配色搞反（中国场景涨红跌绿）。
- [ ] 交互控件在触屏上够不着（< 44px）。
- [ ] 结论藏在第 5 屏 → 提到 Hero。
