## 第一章 Idea 确定方法（如何确定自己的idea）

### 1.1 两种科研范式：启发式 vs 目标式

- **启发式科研**（新手常用）：从一篇引人注目的 SOTA 论文出发 → 深读找出其 failure cases（如某模型对高噪声数据表现差）→ 针对失败案例设计新方法。
  - 优点：上手快，基于已有工作，新手能快速建立领域认知。
  - 缺点：改进幅度不大则难受关注；方向热门、极易"撞车"；要做出突破需极深洞察。
- **目标式科研**（文档强烈推荐）：
  1. 设定长期、有挑战性的科研目标；
  2. 制定研究路线图，拆解为一系列关键任务，每个任务独特且有挑战；
  3. 基于技术现状与领域空白，选择一个代表性强、与长期目标相符的任务深入，发现现有算法不足并设计新算法。
  - 优点：研究者是"引领者"而非 follow-up；研究成体系、每步服务总目标；**即使方法没完美解决问题，问题驱动式研究也更容易被审稿人接受**。
  - 难点：制定好路线图需要对领域、技术趋势有深远理解。

### 1.2 研究路线图的构建四步法

1. **文献回顾与整理**：广泛阅读，列出领域关键论文（代表主要成就与进展）。
2. **识别里程碑任务**：找出公认的重要进展任务，并记录提出这些任务的"初始论文"（创新/转折点所在）。
3. **梳理研究方法和表征**：按论文采用/提出的关键方法与表征（算法、技术流程、数据表示）分类，标记引入它们的原始论文。
4. **细化研究类别**：进一步细分出更小的研究主题/趋势（属"第三类创新性"），判断哪些方向已饱和、哪些仍有空间。

之后：在分类结果中寻找**尚未被充分探索的领域**作为创新出发点 → 通过研讨会、组会、一对一交流与专家验证想法 → 设定实际研究目标 → 研究中持续评估、动态调整路线图。

### 1.3 预审法：用新技术打磨与升华 idea

- 新工具/技术出现（如 NeRF）时**迅速学习**——快速跟进者（VolSDF、NeuS 作者）都取得了瞩目成果。
- 思考如何用新技术完成自己路线图上的某个关键任务（如 Stable Diffusion → DreamFusion）。
- 考虑交叉领域合作（CV×生物、AI×医学），新 idea 常出现在交汇点。
- 持续反思 idea 是否仍匹配最新技术趋势与社会需求，不匹配则及时调整。

### 1.4 Checklist：Idea 确定自检清单

- [ ] 我走的是启发式还是目标式路线？能否把它挂到一条长期目标链上？
- [ ] 我列出了领域关键论文清单，并标注了每条线的"原始论文"吗？
- [ ] 我按方法/表征给文献分过类吗？能说出哪 2-3 个方向已饱和、哪 1-2 个仍有空白？
- [ ] 我的 idea 有明确对应的"里程碑任务"或"领域空白"吗？
- [ ] 我与导师/同行至少验证过一次该 idea 并拿到反馈了吗？
- [ ] 最近 6 个月出现的新技术中，有能嫁接到我路线图上的吗？
- [ ] **决策规则**：若一个 idea 只是"改进他人方法且提升幅度不大"→ 警惕撞车，重定位；若是"目标/问题驱动 + 填补空白"→ 即使方法不完美也值得做。

## 第二章 实验思路（顶会顶刊的实验思路是如何炼成的）

### 2.1 实验设计的总逻辑：抽丝剥茧 + 以终为始

- 设计前先广泛收集文献 → 归纳共同点/差异点/研究空白 → 提炼实验设计初步思路。全程回答两个问题：**这个问题为什么值得研究？研究它对领域有何重要性？**
- 把研究切入点**分解为若干具体子问题**，子问题的解决构成实验设计主线；用逆向思维（从目标倒推）逐层拆解。
- 对已确凿的结论可"接着往下挖"；对有争议、证据不足的问题保持质疑，围绕其设计新实验。
- 研究题目与实验方案是相互影响、迭代精化的：随方案细化，题目认知也会变清晰，需频繁回查文献。
- **图片/文字分块-归纳-重组网读法**：把文献中实验方案的图表与文字分块提取 → 归纳同类方案共性与个性 → 对比整合多个方案，理解每种设计背后的科学原理与考量。图像比文字更直观，集中浏览领域图表可快速掌握"需要做哪些表征和测试"。

### 2.2 四种"以终为始"的实验执行方法

实验反馈常见三种：重复性好 / 重复性差 / 复杂模式（部分好部分差）。后两者是常态。逐个步骤凭直觉排查效率低且易偏离初衷，改用：

1. **MVP 法**（最小可行产品）：先构建最小化、核心功能的版本验证可行性——新算法先用简单数据集+基本结构验证，不立即上复杂真实场景。核心是"从简单做起、快速验证关键假设"，避免在不可行项目上重投入。
2. **替换法**：用已验证的成熟方案替换自研步骤——成熟算法（如 Canny）、标准数据集（ImageNet/COCO/SQuAD）、开源框架与预训练模型（PyTorch/TF）、容器化环境（Docker/云模板）、仿真替换真实环境。目的：省时 + 保准确 + 可复现。
3. **排除法**：逐步缩小问题范围——"屏蔽"某模块使其输出固定参数，观察输出是否符合预期，二分式定位根源；或将问题拆成小模块逐一单独测试。避免盲目试错。
4. **节点测试法**：把整体实验方案切为若干关键节点（里程碑：数据收集、算法设计、模型验证等），**为每个节点预设可验证的目标**（具体数值/图形/成果）；到达节点即核对偏差，达标则继续，不达标则当场定位调整。这是高质量成果背后的"秘密武器"。

### 2.3 实验规划迭代表与极致分解

- **实验规划迭代表**：明确实验目标、预期结果、所需资源（算力/工具/平台/数据）、时间安排；随进展动态调整。数据要兼顾质量、完整性与隐私伦理；软硬件工具（语言、开发环境、测试平台、性能分析工具）提前规划。
- **极致实验分解**（细节决定成败）：
  1. 摒弃"无法进一步分解"的预设——今天的"固定/最优"方案明天可能被替代（sigmoid/tanh → ReLU；特征工程 → 端到端学习）。
  2. 深挖看似固定的部分：激活函数是否适合本任务（ReLU vs Leaky ReLU vs Swish）？预处理方法有无更优选择？经典算法的默认参数/阈值（SVM 正则化参数、K-means 的 K）必须做**参数敏感性分析**。

### 2.4 想法快速验证

先确定实验终点 → 逆向确定关键步骤 → 评估哪些步骤可简化/省略/替换，只保留验证核心想法的最小步骤；先在简化/模拟环境测基本可行性，能用现成工具先用现成工具。**先确认 0→1 可行，再考虑 1→100 的完善优化。**

### 2.5 良好实验习惯（审稿人看不到但决定成败）

- **实验步骤记录**：实验记录本左栏按时间记操作与条件，右栏记关键信息/备忘；复杂实验可用视频/录音（"行车记录仪"式留证）。
- **实验编号与版本管理**：所有版本（含失败的）唯一编号并与记录关联；用 Git 管理代码与数据版本，配注释/文档/日志。
- **实验分析**：不盲目连跑实验；定期评估数据，重点关注异常值与偏离预期的结果，发现问题及时调整策略。
- **实验可视化**：Matplotlib/Seaborn（统计）、TensorBoard（深度学习训练过程）；好图表在写作和汇报时"比数页文字更有说服力"。

### 2.6 Checklist：实验执行清单

- [ ] 我的实验能拆成几个子问题/节点？每个节点有可验证的预期结果吗？
- [ ] 每个环节都问过：有没有现成的成熟算法/数据集/工具可以替换自研？
- [ ] 出问题时不逐行盲查，而是用排除法（屏蔽模块→固定输出→二分定位）了吗？
- [ ] 对所有"默认参数"做过敏感性分析了吗？
- [ ] 开始大实验前，0→1 的最小验证（MVP）通过了吗？
- [ ] 代码/数据有 Git 版本管理，实验记录本左右分区在维护吗？
- [ ] 定期（而非事后）分析数据与异常值，并即时调整方案了吗？

> 注：本章的"节点测试 + 参数敏感性 + 对比文献图表"即顶会实验中 baseline 选择、消融（排除法逐模块屏蔽）与对比实验的底层逻辑——审稿人期待的是**每一步设计都有明确目的、可追溯、可复现、与主故事线紧密相关**的实验体系。

## 第三章 高水平写作思路与方法

### 3.1 核心框架：Fact–Logic–Opinion

高水平写作的本质：**依托事实（fact/evidence），通过合理的逻辑（logic），阐明观点（opinion）和贡献（contribution）**。写作前先回答两个"为什么"：

1. **你为什么做这项研究？**（新知识？解决争议？填补空白？）
2. **为什么是你来做？**（别人做到哪了？你新增了什么贡献？）

贡献的三种形式：填补无人关注但重要的空白；解决长期分歧；澄清被误解的常识（甚至改写教材）。这些关键信息主要在前言传达。

**分清观点与事实**（三个典型错误模式）：
- 观点无证据：说"transfer learning 有优势"却不引用文献也无实验支撑 → 要么引文献，要么后文给出实验。
- 事实→观点的逻辑跳跃：像素密度+15% ≠ 直接得出"视觉更清晰、可用于医学影像"，中间逻辑需要更多证据，应用结论需进一步验证。
- 缺少对比基准：说"500 tps、10ms 延迟说明高效"，却不给业界基准/与其他算法的对比 → 无背景信息，读者无法判断。

**桥梁模型**：每个实验结果是起点，每个观点是终点，逻辑是连接的桥；多个观点串联/并联形成论文主旨（与标题呼应）。**不能因为怕论证不严就只描述实验不下观点**——实验结果存在的意义就是支撑核心论点。

### 3.2 从知识库到素材库：论文写作流程

1. **明确贡献并搭框架**：确保每一部分、每一图表、每一句话都与贡献相关；结果的组织逻辑在实验阶段就开始形成。
2. **"蜜蜂采蜜"三步**：搜集素材（广泛从代表性文献采集，避免偏见）→ 提炼归纳（分析总结提取关键信息）→ 成文（结合自己的实验结果写成论文）。"读书破万卷，下笔如有神"。
3. **知识库贯穿科研生涯**：选题、研究、写作共用同一个知识库（专设写作引用分类），不要每个阶段另建，避免重复低效。
4. **先写前言**：前言写作能加深对全文核心思想的理解，使后续结果与讨论更有针对性。
5. **"树木"写作模型**：核心思想是树根 → 先写提纲，明确每段要点及逻辑关系（主干、分支）→ 最后才打磨句子（叶子）。不要一上来就抠字句。
6. **前言的常见脉络**（从素材库归纳）：背景 → 领域关键问题 → 前人进展与不足 → 引出自己的研究。
7. **结果与讨论的三层**：结果是什么（描述）→ 为什么是这样（深入探讨）→ 与全文的关系是什么（联系其他结果或已报道研究）。避免"只因为别人做了某实验就模仿"的误区，每个实验都必须服务主题。

### 3.3 横向与纵向思维拓展

- **横向**：与前人研究对比定位自己的工作——性能差异的原因是什么？用"源头思维"追问本质（速度由什么决定：复杂度？数据结构？并行？噪声处理？），并关注前人未报道的新现象。
- **纵向**：把某一部分的讨论与其他实验结果结合。写作卡壳（不会写前言/讨论）往往是素材搜集不全。
- 两种检索技能：**自上而下**——构建同义关键词库+检索式，用 Endnote 二次搜索、归纳、分组；**自下而上**——用图片搜索/全文搜索（搜算法名→看流程图→定位文献→搜集描述段落）精准补料。

### 3.4 观点/综述论文写作五步法

1. 确定关键词（含同义词、上位技术词；从导师/同行推荐的核心文献标题摘要反查检索词库缺漏）。
2. 构造检索式并在 Scopus 等测试：先求全再逐步收窄（如关键词限定标题），数万→7000→2000 篇；不相关结果导入 Endnote 分类筛选。
3. Endnote 知识库整理：二次搜索与归纳分组，明确论文切入点与核心观点。
4. 确定框架（一二级标题 + 各标题下内容 + 逻辑顺序）。
5. 完成全文：不确定处用检索技巧找表达与素材，规范引用。

### 3.5 Checklist：写作流程清单

- [ ] 我能用两句话说清"为什么做"和"为什么是我做"吗？
- [ ] 每个观点背后有事实（实验/引用）+ 逻辑桥吗？有没有结论先行的跳跃？
- [ ] 所有性能结论都给了对比基准/背景数据吗？
- [ ] 框架先行：提纲（主干分支）→ 段落要点 → 句子（叶子）的顺序执行了吗？
- [ ] 图表是否每张都直接服务论文贡献？
- [ ] 每个结果都按"描述→为什么→与全文关系"三层写了吗？
- [ ] 检索既有自上而下（关键词库+Endnote 分组）也有自下而上（图片搜索）吗？
- [ ] 参考了他人内容处都规范引用了吗（学术诚信）？

## 第四章 常见问题与误区（写作常见问题与误区）

格式与细节是审稿人对"专业水准"的第一印象——引用混乱、图表难懂会让审稿人直接质疑论文可信度；在初稿阶段就管好这些"小事"，后期才能专注内容深度。

### 4.1 影响表达的问题

- **定语过长**：一句话塞入多层修饰（如超长的后置定语链）→ 拆成 2-3 个短句重写。
- **句子过长**：整段一句话、停顿过多，传达低效且令读者厌烦 → 按逻辑切成多个短句，用 This / Consequently / For applications requiring... 衔接。
- **规则**：句子里一次只表达一个核心信息；复杂因果关系拆步陈述。

### 4.2 格式问题

- **字符与标点**：英文论文全部使用英文半角字符——中文全角引号、宋体方括号都是输入法未切换的典型错误；漏句点、多/少空格常见。可用 Grammarly 或 Word 显示编辑标记排查。
- **伪代码/代码格式混乱**：缩进、冒号、大小写必须规范一致。
- **字体格式统一**：全文字体、字号、样式一致；上下标正确（O(n²) 不能写成 O(n^2) 的模糊形式）。
- **缩写规范**：首次出现给全称，如 "AI (Artificial Intelligence)"，之后直接用缩写。
- **工具命名统一**：写正式名称+版本（"MySQL 8.0"），不写笼统的"某数据库"。

### 4.3 参考文献问题（重灾区）

- **规范引用**：引用前必须已下载并通读全文，确认该文献确实提到正文所述内容；若它也是转引，必须**追到最初源头**。不能因某文献这样写就盲信——旧观点可能已错、实验可能有缺陷，每个结论性表述都要从源头思考其正确性。
- **正文引用格式**：序号格式、标注位置错误可用 Endnote 等工具的期刊 style 文件自动生成。
- **文献列表错误**：期刊缩写不正确（用 Endnote 的 Tools → Term Lists 检查；缺条目则先确认全称再新建）；作者名拼写错误直接在管理工具中改；导入导致的标题空格/上下标错误（e² 写成 e2）**必须在 Endnote 内改**——在 Word 里手改会在刷新文献时丢失。

### 4.4 最终审查

完成撰写与格式修改后做最终审查：捕捉错别字/语法错误，确认内容与格式达到出版标准；请导师等第三方审查获取意见。

### 4.5 Checklist：投稿前纠错清单

- [ ] 无超长句（一句一信息）与多层定语？朗读一遍检查停顿是否自然。
- [ ] 全文无全角字符、标点半角统一、无多余/缺失空格？（Grammarly + Word 编辑标记）
- [ ] 字体字号样式统一，上下标（含公式与文献标题）正确？
- [ ] 所有缩写首次出现给全称；工具/软件带版本号？
- [ ] 每条引用都读过原文、追到源头、与正文表述一致？
- [ ] 引用格式用文献管理工具的期刊 style 生成，而非手工？
- [ ] 文献列表的期刊缩写、作者名、标题上下标都在管理工具内修正过？
- [ ] 提交前请导师/第三方做过一轮最终审查？
