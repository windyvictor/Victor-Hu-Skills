# R2 — 表格与图（Diagrams）

## 1. 判据：什么时候图优于文

文字是**一维线性**的介质。当要表达的信息本身是**二维或更高维**的时候，文字就开始付"线性化
税"——把并行结构压成先后顺序，读者再在脑内还原。这一步就是重读的来源。

命中任一条，就该出图：

| 信号 | 内容形态 | 合适的图 |
|---|---|---|
| 结构 | 有哪些部分、各部分什么属性 | 概念图 / 树形图 / 分层图 |
| 关系 | 谁连谁、谁影响谁、耦合方向 | 关系图 / 有向图 / 依赖图 |
| 流程 | 先后顺序、分支、循环 | 流程图 / 泳道图 |
| 阶段 | 状态迁移、触发条件 | 状态机图 / 状态条 |
| 时序 | 谁在什么时候和谁说话 | 时序图 |
| 对比 | 同一维度下多个对象的取值 | 对比矩阵 / 雷达图 / 分组柱状图 |
| 数量 | 趋势、分布、相关性、构成 | 折线 / 散点 / 直方 / 饼 / 桑基 |
| 空间 | 位置、方向、距离、布局 | 平面图 / 剖面图 / 三维示意 |
| 过程演化 | 同一对象随时间变化 | 多帧并排（不要做动画图） |

**反向判据**：如果内容本来就是一条直线上的三件事，**不要画图**。流程图画成一行箭头只是把
文字重新排了一遍，没省任何力气。

## 2. 绘图铁律

1. **一图一主张**。图上只能有一个结论。想放两个结论就出两张图。
2. **图题写结论，不写类型**。
   - 差："图 1 系统架构示意图"
   - 好："图 1 识别模块与规划模块共享同一状态编码器，因此只需训练一次"
3. **标签必须短**。中文 ≤ 6 字，英文 ≤ 3 词。放不下就加编号，正文里解释。
4. **颜色承载语义，且全篇一致**。同一个颜色在任何图里都表示同一类东西。
   中国金融场景遵守本地惯例：**涨红跌绿**（与欧美相反）。
5. **主题自适应**。浅色主题：浅底深字；深色主题：深底浅字。**绝不允许深底配深色字。**
6. **矢量优先**。用 SVG，可缩放、可改字、可进 PPT。位图只在必须时使用。
7. **不用图做装饰**。图要承担信息量；纯装饰图删掉。
8. **坐标系必须标轴名与单位**。缺单位的数据图等于没画。

## 3. 输出方式（按场景选）

| 场景 | 做法 |
|---|---|
| 对话中即时展示 | 用内联可视化能力（SVG 或内嵌 Chart.js），随手给，不落盘 |
| 需要交付、可编辑 | 落盘 `.svg`；需要图片格式时再转 PNG |
| 科研出图（论文/报告） | 用 Python 出图，遵守期刊规范：字号 ≥ 7pt、线宽 ≥ 1pt、单栏宽 8.5cm / 双栏 17cm、300dpi、无边框、无网格或极浅网格、色盲友好配色 |
| 需要嵌入网页 | 内联 `<svg>` 或 CDN 引入图表库，见 `rung-3-html-explainer.md` |
| 需要进 PPT | 出 SVG，或直接生成原生可编辑形状 |

## 4. 常见错误清单（出图后逐条自查）

- [ ] 图题是"XX 示意图"这种没有信息量的标签 → 改成结论句。
- [ ] 一条直线上的三步画成了流程图 → 改回文字。
- [ ] 颜色只是为了好看，没有语义 → 要么给语义，要么改单色。
- [ ] 深色背景上用了深灰文字 → 改对比度。
- [ ] 数据图没标单位 → 补上。
- [ ] 一张图里有五个结论 → 拆图。
- [ ] 中文标签换行断在词中间 → 手动控制断行。
- [ ] 图里用了图外才定义的缩写 → 图内先给全称。

## 5. 与阶梯的接口

- 图的**标题、图注、标签**都要过 R1 的受控规则。
- 若读者会问"如果参数变了会怎样" → 不要出静态图，升到 **R3**（可交互）。
- 若需要看着它一步步演化 → 不要出多帧并排，升到 **R4**（视频）。
