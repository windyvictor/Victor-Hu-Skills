# 核心提示词（中文通用场景）

以下提示词按原样保留（便于整段复制使用），使用时把占位符替换为用户提供的文本。

> **说明**：本技能的方法框架与提示词由本项目整理撰写（详见 README「参考资料 / 灵感来源」，标注为原创方法论）。此处「按原样保留」指不改写本技能自身的提示词，以便直接套用。

---

## §1 科研论文通用"去 AI 味"提示词

**适用**：论文初稿、AI 润色稿、基金申请书，以及已写完但感觉"AI 味很重"的文本。未指定章节时的默认选择。

```text
【上传原文】

修改下面的科研文本。

你的任务不是单纯润色语言，而是在严格保持原始科学含义的前提下，降低模板化、机械化和明显的 AI 写作痕迹，使文本更接近研究者真实撰写和修改后的学术表达。

请遵循以下原则：

1. 保留原文中的研究事实、数据、实验结果、变量关系、专业术语、公式、引用和限定条件，不得擅自改变科学含义。

2. 不得补充原文没有提供的实验结果、机制、数据、文献结论或因果关系。信息不足时宁可保留谨慎表述，也不要自行推断。

3. 以连续、自然的学术段落为主。除非信息确实属于并列条件、实验步骤或分类比较，否则不要主动改成项目符号、编号列表或表格。

4. 每个段落围绕一个明确问题展开。句子之间应存在真实的逻辑关系，例如：

研究问题 → 已知事实 → 当前不足 → 本研究处理方式；

结果 → 证据 → 解释 → 科学含义。

不要把彼此相关但缺少逻辑连接的句子简单堆在一起。

5. 对普通背景信息保持简洁，对真正决定论文价值的内容写得更具体，包括：

研究假设、方法选择依据、关键机制、创新点、重要实验结果及其解释。

不要出现"背景解释很多，真正关键的一步却一笔带过"的情况。

6. 优先使用准确、具体的名词和动词。避免用抽象词包装简单事实。

例如，与其写：

"该策略有效促进了系统性能的提升"

如果原文有具体信息，应优先写：

"加入 X 后，模型在 Y 数据集上的准确率由 81.2% 提高至 86.7%。"

7. 删除或改写没有实际信息增量的套话，例如：

"值得注意的是"
"需要指出的是"
"众所周知"
"不难发现"
"显而易见"
"具有重要意义"
"提供了新的视角"
"为……奠定了基础"
"进一步推动了……"
"充分体现了……"
"具有广阔的应用前景"

这些表达不是绝对禁止。如果句子能够回答"具体值得注意在哪里""具体产生什么意义"，可以保留相应含义，但应直接写出事实。

8. 减少机械的转折结构，尤其避免频繁使用：

"不是……而是……"
"不仅……而且……"
"这并非……而是……"
"与其说……不如说……"

只有在两个概念确实需要比较或纠正误解时才使用。

9. 不要为了显得高级而制造复杂名词、复合标签或不必要的新概念。优先使用本领域已经存在且含义明确的术语。

10. 不要在每段末尾自动添加总结句。只有当总结能够推进下一步论证时才保留。

11. 避免连续使用完全相同的句式，但不要为了"句式多样性"机械替换同义词。句式变化应服务于逻辑。

12. 谨慎使用因果表达。

如果研究只能证明相关性，不要改写成因果关系。

如果机制尚未验证，应使用 suggests、may、is consistent with、可能、提示等符合证据强度的表达。

13. 保留必要的专业术语。所谓"减少术语"不是把专业论文写成科普文章，而是删除没有帮助的术语堆砌。

14. 修改完成后重新检查：

每一句是否提供了新信息、必要解释或逻辑连接？

如果一句话删除后几乎不影响段落含义，优先考虑删除或合并。

输出修改后的完整文本。

不要解释你的写作过程。

不要逐句展示修改记录。

除非我另外要求，否则只输出最终版本。
```

## §2 专门处理"满篇都是套话"

**适用**：内容没错，但每句话都似曾相识、读起来空洞。可单独使用，也可作为 §1 之后的补刀。

```text
请检查下面文本中的模板化学术表达。

重点寻找三类句子：

第一类，没有增加事实，只用于强调，例如"值得注意的是""需要指出的是""显然""重要的是"。

第二类，只有抽象评价而没有具体对象或证据，例如"具有重要意义""表现出巨大潜力""提供新的视角""进一步推动了相关研究"。

第三类，机械制造转折和强调，例如"这不仅是……更是……""这不是……而是……""不仅能够……同时还能够……"。

修改原则：

如果删除这些表达后意思完全不变，直接删除。

如果作者真正想强调某件事，不要使用评价词强调，而是写出值得强调的具体事实、差异、机制、数据或条件。

不要简单把一个套话替换成另一个套话。

不要为了降低重复率而堆砌同义词。

保持科研论文正式、克制、精确的语气。

原文：

【粘贴内容】
```

## §3 解决"背景写了一大堆，关键技术一笔带过"

**适用**：Methods、Results、技术创新点，以及基金申请书中的研究方案。

```text
请从专业研究人员的阅读视角检查下面这段内容。

重点判断：

作者在哪些地方花了过多篇幅解释读者已经能够理解的背景？

哪些关键技术步骤、推理过程、参数选择、机制解释或方法设计被过度压缩？

请重新分配篇幅。

对于常识性背景，只保留理解后文必需的信息。

对于决定研究是否成立的关键步骤，需要给出足以让同行理解的解释，包括：

为什么采用这一方法；

这一方法解决了什么具体问题；

关键变量或条件是什么；

结果如何支持对应结论。

不要凭空补充原文没有提供的技术细节。

如果某个关键逻辑缺少必要信息，请保留原文能够支持的表述，不要替作者编造解释。
```

## §4 约束式改写（防止 AI 自由发挥）

**适用**：用户要求"只改某几处，其他别动"，或需要严控改动范围时。**这也是替代"帮我润色得更专业一些"这类开放式指令的标准写法。**

背景：科研写作中最危险的提示词只有一句"帮我把这段话润色得更加专业、学术一些"——"更加专业"没有明确标准，模型会靠增加术语、连接词、抽象名词、长句和评价性措辞来制造"专业感"，直接生成典型 AI 文风。正确做法是明确告诉模型哪些不能动、只解决哪些问题、没有证据时不能做什么。

```text
保持实验事实、数据和结论不变。

只解决以下三个问题：

1. 删除没有信息量的套话；

2. 补强现有文字中已经存在但表达不清楚的逻辑关系；

3. 让关键方法和结果获得足够解释。

不要增加研究结论。

不要新增引用。

不要自行推测机制。

不要扩大创新性。

不要为了"学术感"增加复杂词汇。

直接输出修改结果。
```

按需替换"三个问题"的具体内容，其余约束条款保持不变。
