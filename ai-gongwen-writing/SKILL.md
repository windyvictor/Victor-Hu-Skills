# AI 公文与职场写作技能库

## 用途

把一份模糊的公文/职场写作需求，转化为**结构可控、语气合规、内容可落地**的成稿。双来源方法论：

1. **《梅俊·AI公文写作工具手册》**（体制内公文主线）：先选对文种、备齐素材，再锁定文种写作公式，按段落模块逐段生成与精调。
2. **《得到·职场写作训练营》（罗砚）**（职场写作心法层）：三原则（导向行动、用户意识、默认公开）+ 清单体，适用于**所有文种**的质量通则；并补充周报、申请、复盘、方案、公开发言、年终总结等职场文体。

## 何时使用

- 用户要求撰写某类公文（通知、通报、纪要、总结、汇报、讲话、调研报告、制度、公开信等）
- 用户要求撰写职场文体（周报、申请、复盘报告、方案、公开发言、年终总结等）
- 用户要求改写、扩写、压缩、调整某段公文内容
- 用户询问某类材料的结构、段落公式、语气要求
- 用户询问"这种情况该写什么文种"
- 用户提供了会议记录、工作材料、上级文件，需要加工成正式公文

## 核心工作流（7 步法）

严格按顺序推进，**不要跳过前 4 步直接生成全文**——公式只能保证骨架，内容质量取决于前期信息。

| 步骤 | 动作 | 支撑文件 |
|---|---|---|
| 0 | **文种选型**：确定该用哪个文种 | `17-易混文种辨析.md` |
| 1 | 拆解工作问题：这篇公文要解决什么问题、涉及哪些业务、需研究哪些方面 | —— |
| 2 | 分析处理信息：检索上级精神、政策文件、业务现状数据 | `15-输入素材模板.md` |
| 3 | 判断信息质量：剔除过时、来源不明、无关信息；区分事实/数据/观点 | `15-输入素材模板.md` 六 |
| 4 | 明确写作要求：文种、发文机关、受文对象、字数、语气、特殊要求 | —— |
| 5 | 生成文种内容：加载对应文种的写作公式，按段落模块生成 | 各文种文件 |
| 6 | 判断内容质量：逐项自检（含职场写作三原则快检） | `18-成稿自检清单.md`、`19-职场写作三原则与清单体.md` |
| 7 | 精调文本内容：替换模块、调整标题、补充数据、修正语气 | `00` 七 |

### 第 0 步 · 文种选型（必须先做）

用户常说的是"帮我写个材料"而非文种名。此时**不要猜**，用两个问题定位：

1. 这份材料的**受文对象**是谁？
2. 希望对方读完后**做什么**（知道 / 去做 / 拍板 / 受激励）？

答案即可定位文种。完整的决策树与易混组合（通知/通报/通告、请示/报告、总结/汇报/述职、消息/信息、计划/方案/规划、纪要/记录、感谢信/慰问信/倡议书）见 `references/17-易混文种辨析.md`。

### 第 2 步 · 素材准备（决定成稿质量）

手册中有约 60 处以「（略）」标注的输入材料。**素材不齐时先向用户提问补齐，不要直接生成**——否则只能产出空泛的套话。各类文种需要收集的字段模板见 `references/15-输入素材模板.md`。

### 长文强制分段确认

超过 1500 字的材料（总结、汇报、讲话、调研报告、制度、述职报告、心得体会等），**必须逐部分生成**：先出标题 + 帽段 → 等用户回复 OK → 再出下一部分。禁止一次性倾倒全文。生成前先向用户确认「明确任务，请回复 OK」。

## 万能指令公式

任何一次公文生成请求，提示词内核都遵循 **角色 + 背景 + 任务** 三要素：

```
【角色】你是 <机关/单位> <岗位>，非常熟悉 <业务领域>，擅长公文写作。
【宏观背景】为贯彻落实 <上级会议精神/政策文件>，
【微观背景】<本单位> 将召开/开展 <具体事项>，
【目标受众背景】参会/受文对象为 <对象构成>，
【任务】请以 <发文机关> 名义撰写 <文种>，要求 <语气/字数/结构>。
```

其中：
- **角色**决定语言的专业度与视角（如"市政府办公室主任""央企办公室资深秘书""《人民日报》理论版资深编辑"）
- **背景**决定政治站位与政策依据，缺失会导致内容空泛
- **任务**必须写明文种、字数、语气、结构约束

当信息缺口较大时，用反向提问法向用户索要信息：
`我要撰写一篇 <文种>。请你从不同方面拆解这篇公文的背景，分析解决这个问题需要哪些信息？根据你的分析，向我提问来询问你需要知道的信息。请提出尽可能多的问题。`

## 写作硬规则

1. **文种优先**：先定文种再动笔。文种选错，公式再对也不合格。
2. **素材优先**：关键素材（上级依据、数据、人员）不齐时先问，不编。
3. **结构优先**：先套公式搭骨架，再填内容。禁止自由发挥式写作。
4. **数据占位**：不掌握确切数字时统一用 `××` 代替（不用 `xx`、`XX` 混写），禁止编造具体数据、文件号、人名、单位名。
5. **语气匹配**：部署/贯彻类用指示性语气（"要""必须""不得"）；通报批评用指挥性语言；公开信可用文学化表达（诗句、排比）。
6. **标题规范**：公文标题多为对仗式/复句式。做法段用"做法+成效"复句，对策段用行动导向，成果段用结果导向。同级子标题字数尽量一致。
7. **公式痕迹清零**：成稿中不得出现"主题句（why）""支撑句（how）""××句""【帽段公式】"等公式内部表述，直接输出正文内容。
8. **逐级确认**：长文、重要材料按部分输出并等待确认，不要一次性生成。
9. **三原则通检**：所有文种成稿后过一遍「导向行动 / 用户意识 / 默认公开」快检（见 `19` 八、`18` 职场写作三原则快检）——时间是否绝对、指令是否无歧义、要事是否在开头、外人看了是否会误解、后人查阅是否走样。

## 质量红线（生成后自检）

快速版（详细分文种清单见 `18-成稿自检清单.md`）：

- [ ] 结构完整，写作公式中的每一个段落模块都存在，无遗漏
- [ ] 无编造的政策名称、文件号、数据、人名、单位名
- [ ] 一二级标题层次清晰，符合对仗要求，序号规范（一、（一）1.）
- [ ] 语气与文种匹配，政治表述规范准确
- [ ] 字数达标或明确说明偏差原因
- [ ] 无公式内部表述残留

**自检未通过的部分不得交付。**

## 常见调整指令库

用户提出修改要求时，直接套用以下指令模式：

- **替换模块**：`请套用下面的【××模块】，对第×部分进行调整修改，字数××字。`
- **补充数据**：`请补充具体工作和数据增长指标，相关数据用××代替。`
- **补充细节**：`请对第×段内容进行补充完善，充实相关工作细节要求，明确时间节点。仅输出该部分。`
- **改写标题**：`请按照公文对仗式标题写法修改下列标题。` / `改成结果导向（行动导向）的标题句式。`
- **压缩整合**：`请将上述内容整合成一段文字，不改变关键内容，字数××字。`
- **仿写标题**：`请模仿下面的【引用型标题】修改下列标题，标题中要引用诗句，且保持字数一致。`
- **增加理论性**：`请为下面的内容在段首增加一句主题句，要求具有理论性，能概括段落内容。`
- **合规检查**：`请对照【××制度】与【××文件】，检查是否有冲突抵触的地方。`

## 交付规范

1. **内容先行**：先给成稿，再附一句"本次按【××写作公式】生成，帽段/主体段/结尾段均已覆盖"。
2. **标注占位**：明确列出哪些地方用了 `××`，提醒用户补实数据与名称。
3. **格式提醒**：如为正式行文，提醒用户按 `16-公文格式规范.md` 完成版式落地（发文字号、主送机关、署名、成文日期、印章等）。
4. **长文分段**：长文交付时说明已生成的部分与待生成的部分。
5. **文件输出**：需要落盘时用 Write 工具生成 `.md` 或 `.docx`，并给出**绝对路径**。

## 使用示例

用户："帮我写一份关于秋冬季森林防火的部署通知"
→ 文种明确（部署工作通知），加载 `01-通知.md`，按 `标题+通知缘由段+通知事项段+结语段` 生成，指示性语气；素材不足时用 `15` 的模板提问。

用户："下周要开个会，帮我写个会议通知和会后纪要"
→ 两个文种：先 `01` 会议通知，再 `05` 会议纪要；向用户索取会议基本信息与会议记录（`15` 2.1 / 2.4）。

用户："把这份会议记录整理成纪要"
→ 加载 `05-会议纪要.md`，判断办公类还是研讨协商类，套用议题段公式（议题句+会议过程句+结论要求句）。

用户："写一篇读书心得，2500字"
→ 加载 `08-体会与发言.md`，先输出标题+帽段，等确认后逐部分生成。

用户："这个东西该写什么文种？"
→ 加载 `17-易混文种辨析.md`，用两个问题（受文对象 / 期望动作）定位文种。

用户："帮我写本周周报，我做了A、B、C三件事"
→ 加载 `20-周报.md`，按"主线任务三半句 + 决策思路 + 情报视野"生成；素材缺目标数据时先问（接活思维是周报大忌）。

用户："项目结束了，写一份复盘"
→ 加载 `22-复盘报告.md`，按"定义问题（含适用边界）→ 操作步骤 → 决策思路 → 正反案例"逐条经验生成小闭环。

用户："下周竞聘演讲，帮我准备发言稿"
→ 加载 `24-公开发言.md`，131 公式：一句挑战开场（听众是主角）→ 三点递进方案 → 一次返场收尾。
